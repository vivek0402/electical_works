# Build design direction B ("Bold and graphic") into the real app

## Context
The user asked to elevate the frontend, rejected a tidy-up as "not major changes", allowed everything to change (layout, colours, typeface, components), then chose **direction B** from three mocked directions and asked for clearer hierarchy: main actions at the top, related things grouped. Five screens are mocked and approved in direction B at `mockups/design-b/` (dashboard, current stock, Stock IN form, complaints list, complaint page). This plan turns the whole Django app into that design.

**Who does what (user's instruction):** Fable only plans and dispatches. Every build, fix and review task below runs in a **Sonnet** subagent (`Agent` tool, `model: "sonnet"`), one at a time, never two on the same files (lesson 2026-10-13).

## What changes and what does not
- **Changes:** templates, `static/css/app.css`, small display-only JS, the menu structure in `apps/inventory/context_processors.py`, read-only dashboard figures, tests and the e2e walkthrough where they assert on markup, `DESIGN.md`, `CLAUDE.md` design section, README screenshots/notes.
- **Does not change:** models, migrations, services (every write), URLs, permissions, form field names and ids, exports, the Django admin. No new write behaviour.

## Design decisions (from the approved mock)
- **Shell:** dark top bar replaces the sidebar. Sections: Home · Stock · Complaints · Defectives · Setup. Each section page has a dark "hero" with the page title, one line of context, the section's main actions, and sub-tabs. Form and detail pages show a "back" link instead of sub-tabs. On phones the top bar scrolls sideways (no hamburger).

  | Section | Sub-tabs | Hero actions |
  |---|---|---|
  | Home | none | Stock IN, Stock OUT, New complaint · Transfer, Adjust |
  | Stock | Current stock, Movements, Low stock (count) | Stock IN, Stock OUT, Transfer, Adjust |
  | Complaints | Overview, All complaints (count), Sites, Technicians | New complaint |
  | Defectives | Overview, Pieces (count), Return batches | Mark defective, New return batch |
  | Setup | Items, Masters (admin only) | New item |

- **Tokens** (copied from `mockups/design-directions/directions.css` `.dir-b` and `mockups/design-b/extra.css`): ink `#0d1321`, page `#f3efe6`, white cards with 18px corners and no border, amber `#f5b301` accent, five type sizes 13/15/18/28/48px, Bricolage Grotesque (headings, figures) + Instrument Sans (text) + Geist Mono (codes), pill buttons 44px high, inputs 48px high. IN blue / OUT orange and the five status tints stay exactly as in DESIGN.md.
- **Screen order everywhere:** main actions → what needs attention → related groups → history.
- **Keep Tabler underneath** (vendored CSS/JS) for the grid utilities, modals, dropdowns and the Tom Select theme; the new `app.css` restyles them. This keeps every modal, picker and script working. The Tabler sidebar layout attribute is removed.
- **Charts become server-rendered CSS bars** (as in the mock), so ApexCharts and the "Table view" toggles go from the two dashboards.
- **Honest labels:** dashboard "needs attention" blocks are links to existing filtered lists (not attended, open over 15 days, low stock, pieces with companies). No "Assign a technician" shortcut and no "Record visit" on the dashboard, because those actions do not exist as one step today.
- **Fonts are vendored** as woff2 under `static/vendor/fonts/` (all three are OFL-licensed); no Google Fonts link in the app.
- **Selectors the tests and walkthrough rely on stay:** `.page-title`, `.alert-success`, `a.code`, `.btn-in`, `.btn-out`, `.lines-table`, `.form-selectgroup-label`, `#gsearch`, `#gresults`, `#form-error`, `#entry-form`, `.undone`, `.zero`, `badge st st-*`, all `name=`/`id=` attributes. They get new styling, not new names. Where a structure truly changes (dashboard tiles, menu markup), the test is updated to assert the same fact on the new markup.

## Screens not individually mocked
Five screens are mocked; the other ~20 follow them by pattern. Approving this plan approves building them without a separate mock each; the user reviews them on demo data after each area task.

| Pattern (mocked screen) | Applied to |
|---|---|
| List (`#list`, `#stock`) | movements, low stock, items, sites, technicians, pieces, return batches, masters |
| Form (`#stock-in`: numbered groups + sticky summary with Save) | Stock OUT, transfer, adjust, item form, new complaint, record visit, mark defective, new batch, site and technician forms |
| Detail (`#complaint`: fact tiles, grouped cards, history) | entry detail, item card, site detail, piece detail, batch detail |
| Dashboard (`#home`) | complaints overview, defectives overview |
| Login | centred card on the dark background |

## Risks
- **Tests tied to old markup** (about 30 assertions, mostly dashboard tiles and menu): updated in the task that changes the markup, asserting the same fact.
- **Postgres 18 vs the project's 16:** the baseline in T0 shows whether anything already differs before the redesign touches it.
- **Hero text on dark and amber backgrounds:** contrast is checked in T6, not assumed.
